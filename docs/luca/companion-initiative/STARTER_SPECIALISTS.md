# Starter specialists — beta.14

Approved scope: the existing cast plus research and writing, useful examples and ordinary delegation. No new team engine, harness, permission policy, Mnemos or Ghost work.

## Cast

- Luca: companion and coordination; answers simple questions directly and owns the returned result.
- Vektor: building and automation; inspect → implement → verify.
- Anima: exploration; find a concrete tension or connection, then make a small artifact or experiment.
- Fifty: design and usability; inspect the experience, choose a direction, make it concrete and inspect the result.
- Trinity: review; test consequential assumptions, distinguish findings from concerns and give a usable verdict. No claim of three-context execution without a real supported run.
- Mira: research; original sources, independent corroboration, contrary evidence, calibrated conclusions and traceable links.
- Coda: writing; purpose and voice, structure before line editing, factual fidelity and a usable draft, never implied publication.

Luca/Vektor/Anima remain the initial active definitions. The other four are catalog entries, not automatically provisioned processes. Every resident uses ordinary configured harness/model selection and existing task, consent and sharing boundaries.

## Implementation

Mira/Coda's complete document packs are in `desktop/src-tauri/resident-packs/`. The native persona registry seeds inactive definitions without replacing stored edits. Resident folder creation uses the existing absent-only pack writes.

`desktop/src/shared/content/starterSpecialists.json` is the common source for role summaries, examples and specialist methods. The catalog offers copy-only examples before its collapsible instructions. The shell's Add Agent dialog exposes that catalog; adding uses the existing resident provisioning/reuse path. It does not create a project or conversation.

Native prompt assembly includes the concrete working method only while the saved portrait and Instructions both exactly match stock. Edits, missing instructions, custom definitions and imported native residents are excluded. The supplement stays within the existing total prompt cap and does not write documents. It describes possible collaborators, never claims catalog entries are online, and retains actual tool/consent/Stop authority.

An unpinned starter uses an explicit global runtime first; when that is unset in an older profile, it inherits the canonical companion's exact local harness. If that harness is unavailable, addition stops with an actionable error rather than switching to another provider or the legacy unconfigured runtime. Explicit agent harness choices remain authoritative.

## Acceptance

1. Fresh and existing definition stores gain Mira/Coda inactive; current active choices and custom fields survive. Repeat load adds no duplicates.
2. New packs seed complete documents without inventing user history. Existing files stay unchanged. Stock methods never attach to edited or imported identities.
3. Add Agent → Browse starter agents exposes all roles and examples. Copy writes exactly the selected prompt and makes no agent/model/permission call. Keyboard, narrow desktop widths and both themes remain usable.
4. Add uses the configured runtime and existing persona identity reuse; failures remain visible. No provider/model pin, source grant or quiet background work is introduced.
5. Each specialist completes a small bounded task with an attributable result; Luca delegates and receives the new specialists' results through existing inboxes. One collaboration demonstrates distinct contributions, not a compulsory multi-agent pipeline.
6. Build only in the shared cache, prepare the existing isolated candidate and preserve the daily app. No publish, push, tag or signing.
