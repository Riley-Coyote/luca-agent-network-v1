# Local Capsule Archive and Outbox Protection

## Scope

The archive retains prior verified Capsule event JSON. The outbox retains exact
signed candidate/pointer JSON until coordinator commit/replay is reconciled.
Both contain sensitive continuity and are encrypted independently from ordinary
app data. This contract does not imply that the whole app database is encrypted.

## Cryptographic format

- AEAD: XChaCha20-Poly1305 with a 256-bit random key and 192-bit nonce.
- Key: generated by the desktop authority plane and stored in the OS keychain as
  a versioned, non-exported local archive key.
- Nonce: CSPRNG-generated for every encryption; nonce reuse under one key is a
  release blocker. A unique `(key_version, nonce)` constraint is persisted.
- Plaintext: exact signed event JSON or exact operation payload bytes.
- AAD: RFC 8785 canonical JSON containing schema, table/domain, owner pubkey,
  resident pubkey, event/operation ID, record type and key version.
- Stored envelope: schema/key version, nonce, ciphertext, AAD SHA-256 and
  creation timestamp. Plaintext, secret keys and local paths are absent.

Decryption reconstructs AAD from authoritative row keys and rejects mismatch,
unknown version, duplicate JSON fields, truncated tags and authentication
failure. Error reports contain only opaque record IDs.

## Lifecycle

- The key is never passed to ACP, model/provider runtimes or the Continuity
  Service.
- Rotation uses a durable journal: create new key version, re-encrypt/readback
  one bounded batch, commit batch cursor, then switch active version. Old keys
  remain until every row verifies under the new version and owner confirmation
  permits deletion.
- Owner identity reset/delete offers explicit protected backup, then deletes the
  archive/outbox key and encrypted rows. A missing key makes rows unavailable;
  it never triggers insecure fallback.
- Normal app/database backups contain ciphertext only. The optional protected
  resident backup decrypts verified event JSON inside the desktop authority and
  re-encrypts it inside the age bundle; it never exports the local archive key.
- Crash recovery can replay an exact signed outbox event only after successful
  authenticated decryption and coordinator/idempotency validation.

## Required proofs

- round-trip and tamper tests for ciphertext, nonce, AAD and authoritative row
  key substitution;
- a high-volume generated-nonce test plus database uniqueness enforcement;
- key missing/locked/corrupt states fail visibly without losing conversation;
- rotation crashes at every journal boundary and resumes without mixed-current
  ambiguity or plaintext residue;
- backup/restore and owner reset/delete lifecycle;
- database, WAL/SHM, logs, screenshots, crash reports, clipboard and debug
  exports contain no plaintext continuity or archive key;
- dependency/license review and known-answer vectors checked across supported
  platforms.
